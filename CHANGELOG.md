# Changelog

All notable changes are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- Wave 7: a convincing offline 3D scene. Two reproducible terrain packs baked from an SRTM tile and an OpenStreetMap extract by `tools/terrain` (rural "Heron Ridge", urban "Osprey Town", fictional names, attribution shipped, raw downloads kept out of git); radar and EO/IR lose a target behind terrain or a building (line of sight in the sim core, deterministic, after the random draws); a new scenario on the rural pack, "Heron Ridge: low approach"; the EO view gains terrain, buildings, trees, sun and moon, ACES tone mapping, height fog, rain and wind, thermal (white-hot, black-hot) and night-vision passes, an SVG reticle with mode and gain readouts, and graphics tiers chosen by an fps probe (Auto, High, Medium, Low). A demo-mode `/bench` route measures frame-rate percentiles at 1080p and saves them as JSON; CI enforces a 1.5 MB gzipped JavaScript budget. `scenario.v1` terrain accepts a pack beside flat ground, and the briefing carries it; `GET /api/v1/terrain/{pack}/{file}` serves pack files. Thermal is a rendering model, not radiometric. English and Hindi (Hindi unreviewed). The floor-laptop benchmark result is not yet recorded.
- Wave 6: a scored debrief. Every finished session is scored by an explainable decision tree per contact (Detect, Classify, Assess, Respond) with capped timing bands, an ROE hard-fail gate, a separately graded structured contact report with a calibration check, penalties for unfixed swaps, splits and merges, signal-detection metrics (hit rate, false-alarm rate, d′ with a log-linear correction) and the first three lessons. The Debrief screen shows the path through each contact in plain language in English and Hindi, with the rule-pack version and scenario seed. A contact-report form joins the decision panel. All weights, bands and tolerances are fictional and editable in the rule pack (new optional `scoring` section). New contract `score-result.v1`, migration 0004 (stored score) and `GET /api/v1/sessions/{id}/score`; the log gains `ledger.first_report` and the ground truth the scorer needs, none of which a trainee receives. See `docs/SCORING.md`.
- Wave 5: a playable live session. A trainee signs in, opens the Session lobby, starts the scripted Harrier Field scenario (day, rural, a quadcopter, a bird flock and a permitted civil drone with a filed flight) and plays it in the browser: an EO view in Three.js, a radar PPI, a track table and a keyboard-driven decision panel (classify, assess, respond, hold fire, cue EO, relabel, merge, split, drop). The simulation runs on the server at 20 Hz over a MessagePack WebSocket; the browser receives only what its sensors and tracker produced. Responses are checked against the fictional rule pack and a blocked response shows the closest rule, what is missing and the pack version. A finished session's hash-chained event log is stored and verified on read. Contracts `live-client.v1` and `live-server.v1` (typed in Pydantic, JSON Schema, generated TypeScript); `scenario.v1` gains optional threat disposition and filed flights, `session-record.v1` a `roe` flag. Event-log endpoints and a 12-client load test harness. English and Hindi (Hindi unreviewed). Scoring and debrief are wave 6.
- Wave 5: the production API image now ships `sim/` and `packs/`; `make prod-check` runs `sim-check` inside it (Q-19).

- Wave 4b: tracker and fusion in `sim/tracking/` (six-state Kalman filter, gated nearest-neighbour association, track lifecycle with coasting, triangulation of bearing-only reports, duplicate-track folding, initiation-exclusion zone); seeded association errors (swap, split, merge) that can only occur where gates overlap; a ground-truth ledger that records them with the true identities and when an operator fix restores them; track commands (relabel, merge, split, drop) and cue-to-track as loggable actions (`action-record.v1` gains five values); the sensor picture wired into `World` (state, hash, snapshot and replay include it; a bare world hashes as before); a seeded simulated AI assist with configured hit, false-alarm and class rates. Every detection, track and assist view a trainee receives carries `data_status` and is labelled reference data while sensor parameters remain unverified (Q-20). No user-facing change yet.
- Wave 4a (step 4): acceptance pass; a cross-model test file pins P(d) monotonicity, weather and light effects, confusion normalisation, provenance and the SENSOR_MODELS.md contents across all six shipped profiles. Wave 4a complete locally; CI confirmation pending. No user-facing change.
- Wave 4a (steps 2 and 3): radar (RCS, aspect, micro-Doppler, clutter and rain), EO/IR (Johnson criteria, day, night-vision and thermal, haze and glare, cueing), RF (link budget, band plan, hopping, RF-silent targets, Wi-Fi and Bluetooth confusers, interference) and acoustic (blade-pass harmonics, spreading and absorption, wind noise) models, five cited fictional sensor profiles, and `docs/SENSOR_MODELS.md`. No user-facing change yet.
- Wave 4a (step 1): sensor framework in `sim/sensors/` (detect template, cueing, degradations, profile loader, confusion tables in `sensor-profile.v1`) and deterministic `atan2`, `exp`, `log` in the sim maths. No user-facing change yet. See `docs/SIM_CORE.md`.
- Wave 3: versioned contracts (`scenario.v1`, `rulepack.v1`, `sensor-profile.v1`, event, action and session records) with exported JSON Schemas, generated TypeScript types and drift checks; one fictional example of each pack.
- Wave 3: deterministic sim core (fixed 20 Hz tick, named PCG64 streams, waypoint kinematics inside class limits), hash-chained event log, snapshot and restore, replay, and golden-file tests. See `docs/SIM_CORE.md`.
- Wave 2: sign-in with server-side sessions, CSRF protection and a login rate limit; role guards; `create-user` command; per-user language and theme.
- Wave 2: self-hosted IBM Plex Sans, IBM Plex Mono and Noto Sans Devanagari; UI primitives; a role-based shell with Status, Profile, About and system-state screens in English and Hindi (Hindi is an unreviewed draft).
